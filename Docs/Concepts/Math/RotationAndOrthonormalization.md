## 개요

3D 그래픽스에서 카메라·캐릭터·객체의 **자세(orientation)** 는 매 프레임 입력에 따라 갱신된다. 자세를 표현·누적하는 일은 본질적으로 **회전된 좌표계의 3 개 정규직교 벡터를 어떻게 저장·관리할 것인가** 의 문제다.

- **회전 행렬** 은 그 3 벡터를 직접 컬럼에 담아 들고 다닌다. 누적 곱으로 float 오차가 쌓이면 3 벡터가 단위 길이·상호 직교 조건을 잃는다 → **정규직교화** 필요.
- **Euler 각** 은 3 벡터를 저장하지 않고 "순차 단축 회전 레시피" 만 들고 다닌다. 직교성 깨질 일은 없지만 **짐벌락** 이라는 본질적 결함을 동반한다.
- **Quaternion** 은 단일 회전축과 반각을 4 개 float 에 인코딩한다. 잉여가 1 차원이라 단위화 한 번이면 복원 완료.

이 문서는 세 표현의 트레이드오프, 짐벌락의 원인, 행렬 직교성 손실의 의미, 정규직교화 알고리즘과 그 선택 기준(보존하고 싶은 축), 그리고 Quaternion 이 직교화를 줄이는 영역과 한계를 정리한다.

## 왜 필요한가

### 문제

- 회전 누적: 매 프레임 회전 행렬을 곱하면 float 반올림 오차가 누적되어 행렬의 직교성·단위 길이가 미세하게 깨진다. 결과적으로 행렬이 **회전 + 미세 스케일 + 미세 비뚤어짐** 으로 변질된다.
- 자세 표현을 잘못 고르면(예: Euler) 짐벌락 같은 별도 함정이 추가된다.
- 깨진 행렬을 그냥 두면 카메라 흔들림, 메시 미세 왜곡, 본 체인의 누적 오차 등 시각적 결함으로 이어진다.

### 해결책

- 회전 누적은 가능하면 **Quaternion** 으로 저장한다(잉여 자유도가 1이라 단위화 1회로 복원 완료).
- 행렬을 직접 다뤄야 한다면 주기적으로 **재정규직교화(re-orthonormalization)** 한다.
- 재정규직교화 알고리즘은 **보존해야 하는 축** 을 기준으로 선택한다 (Gram–Schmidt 입력 순서, 외적 순서).

## 큰 그림: 회전 = 정규직교 기저를 관리하는 일

회전·자세·정규직교화·짐벌락 — 별개 주제 같지만 전부 **3 개 정규직교 벡터를 어떻게 다루는가** 의 다른 측면이다.

**핵심 등식**:

> 회전 행렬 = 회전된 좌표계의 3 개 기저 벡터를 컬럼에 담은 컨테이너

```
회전을 어떻게 표현·저장할 것인가
        │
        ├─ Euler 각:    레시피 3 숫자       → 짐벌락 (분해의 1번-3번 회전축 정렬)
        ├─ 회전 행렬:   3 정규직교 벡터      → 직교성 손실 (정규직교화 필요)
        └─ Quaternion:  단일 (축, 반각)     → 단위 길이 손실만 (단위화 1회)
                            │
                            └─ 결국 모두 "3 정규직교 벡터 = 로컬 좌표계" 를 관리하는 문제
                               │
                               └─ 정규직교화 = 흔들린 좌표계를 다시 정규직교 상태로 보정
                                  (회전 누적 외에도 tangent space / look-at / 외부 데이터 정리에 사용)
```

이 문서는 이 흐름을 위에서 아래로 따라간다.

## 회전 표현 세 가지

### 회전 행렬 (3x3 직교 행렬)

회전 후 좌표축이 향하는 3 개의 정규직교 기저 벡터를 컬럼에 담은 행렬:

$$
R = [\,\mathbf{x}' \;|\; \mathbf{y}' \;|\; \mathbf{z}'\,]
$$

즉 "이 객체가 회전한 결과 X·Y·Z 축이 어디로 향하는가" 를 직접 저장하는 형태. 자세를 그대로 좌표 변환에 쓸 수 있어 직관적이다.

- 저장: **9개 float**
- 실제 자유도: **3** (회전은 3DOF)
- 잉여 자유도: **6** — 이 잉여 공간으로 float 오차가 새어 들어가 직교성/단위 길이가 깨진다.

직교 행렬은 수학적으로 곱셈에 닫혀 있으므로 이론적으로는 누적 곱이 또 다른 직교 행렬이지만, **유한 정밀도 float 곱셈** 에서는 매 곱마다 미세 오차가 들어가 누적된다. 자세한 양상은 [잉여 자유도와 오차 누적](#잉여-자유도와-오차-누적) 참고.

### Euler 각

X, Y, Z 축 회전각 세 개로 자세를 표현. 사람이 읽고 쓰기 가장 편하다.

- 저장: 3개 float, 잉여 자유도 0.
- 단점: **짐벌락(gimbal lock)** — 가운데 회전이 임계값에 도달하면 1자유도가 사라지고 보간이 부자연스러워진다 (다음 섹션 [짐벌락](#짐벌락-gimbal-lock) 참고). 회전 누적/보간 용도로는 부적합.
- 주 용도: 디버그 UI 입력, 애니메이션 키프레임 표시 등 **사람과 주고받는 경계** 에서.

### Quaternion

단위 사원수 $q = (w, x, y, z)$ 로 회전을 표현. 회전 합성은 사원수 곱.

- 저장: **4개 float**
- 실제 자유도: **3**
- 잉여 자유도: **1** (단위 길이 제약 하나)
- 잉여가 작아 누적 오차가 새어들 공간이 한 차원밖에 없고, **단위화 1회** ( $q \leftarrow q / \|q\|$ ) 만으로 정상 상태로 돌아온다.
- 보간(slerp)이 자연스럽고 짐벌락이 없다.

> Quaternion 의 정의·연산(곱·켤레·역수)·축각 변환·slerp·실전 활용 등 상세 내용은 별도 문서로 분리 예정 (Quaternion.md, [#87](https://github.com/jiy12345/DX12GameEngine/issues/87)). 이 문서에서는 **잉여 자유도가 작아 직교화 부담이 적다** 는 측면만 다룬다.

## 회전 행렬에 담긴 축 정보

"회전 행렬에 축 정보가 들어있다" 는 말은 두 가지 다른 의미를 동시에 가진다. 둘을 구분하지 않으면 정규직교화의 대상이 헷갈린다.

### 두 종류의 "축"

| 구분 | (A) 회전된 좌표축 3 개 | (B) 단일 회전축 $\mathbf{n}$ |
|-----|-------------------|---------------------|
| 정체 | 회전 후 X·Y·Z 가 향하는 단위 벡터 셋 | Euler 회전 정리의 "이 회전 전체를 단일 축 둘레 한 번 회전으로 환원" 했을 때의 그 축 |
| 개수 | 3 개 | 1 개 |
| 저장 형태 | 행렬 **컬럼에 직접** 들어 있음 (명시적) | 행렬 안에 **암묵적** — 고유벡터로 추출 가능 |
| 정규직교 개념 적용? | YES (셋이 단위 + 상호 직교 조건) | NO (한 벡터에는 "정규직교" 자체가 정의 안 됨) |
| 정규직교화 대상? | **이것** | 아님 |

### 예시 1 — Y 축 90° 회전

$$
R = R_Y(90°) = \begin{pmatrix} 0 & 0 & 1 \\ 0 & 1 & 0 \\ -1 & 0 & 0 \end{pmatrix}
$$

**(A) 회전된 좌표축 3 개 — 컬럼을 그대로 읽으면 됨**

- 컬럼 0 = $\mathbf{x}' = (0, 0, -1)$ — 원래 X 축이 -Z 방향으로 이동
- 컬럼 1 = $\mathbf{y}' = (0, 1, 0)$ — Y 축은 그대로
- 컬럼 2 = $\mathbf{z}' = (1, 0, 0)$ — 원래 Z 축이 +X 방향으로 이동

각자 단위 길이, 서로 내적 0 — 정규직교 기저 확인.

**(B) 단일 회전축 $\mathbf{n}$ — 고유벡터로 추출**

회전해도 안 움직이는 방향 ($R\mathbf{n} = \mathbf{n}$) 을 찾는다. $\mathbf{n} = (0, 1, 0)^T$ 대입:

$$
R \begin{pmatrix} 0 \\ 1 \\ 0 \end{pmatrix} = \begin{pmatrix} 0 \\ 1 \\ 0 \end{pmatrix} \ ✓
$$

→ 회전축 $\mathbf{n} = (0, 1, 0)$ = 월드 Y 축. 회전각은 trace 공식으로:

$$
\cos\theta = \frac{\text{trace}(R) - 1}{2} = \frac{0 + 1 + 0 - 1}{2} = 0 \Rightarrow \theta = 90°
$$

→ "$(0,1,0)$ 둘레 $90°$ 회전" 한 번으로 환원. 행렬에 암묵적으로 들어있던 단일 회전축 정보.

### 예시 2 — 합성 회전

Y 60° + X 45° 합성:

$$
R = R_X(45°)\, R_Y(60°) \approx \begin{pmatrix} 0.5 & 0 & 0.866 \\ 0.612 & 0.707 & -0.354 \\ -0.612 & 0.707 & 0.354 \end{pmatrix}
$$

**(A) 컬럼 = 회전된 좌표축**

- $\mathbf{x}' = (0.5, 0.612, -0.612)$
- $\mathbf{y}' = (0, 0.707, 0.707)$
- $\mathbf{z}' = (0.866, -0.354, 0.354)$

각자 단위 길이 + 서로 직교 — 검증 가능 (예: $\mathbf{x}' \cdot \mathbf{y}' = 0 + 0.612 \cdot 0.707 - 0.612 \cdot 0.707 = 0$).

**(B) 단일 회전축 — 비자명**

Y, X 어느 쪽도 아닌 **비스듬한 단일 축**. skew-symmetric 추출 공식:

$$
\mathbf{n} \propto \begin{pmatrix} R_{32} - R_{23} \\ R_{13} - R_{31} \\ R_{21} - R_{12} \end{pmatrix} = \begin{pmatrix} 1.061 \\ 1.478 \\ 0.612 \end{pmatrix}
$$

정규화하면 $\mathbf{n} \approx (0.555, 0.773, 0.320)$, 회전각은 $\cos\theta = (\text{trace}(R) - 1)/2 = 0.281$ → $\theta \approx 73.7°$.

→ 이 합성 회전은 "$(0.555, 0.773, 0.320)$ 축 둘레 $73.7°$ 회전" 한 번과 같음. Euler 분해(60° + 45°)와는 다른 시각이지만 같은 회전.

### 어느 쪽이 정규직교화의 대상인가

float 누적으로 행렬이 깨질 때 무너지는 건 **(A)** 다.

```
컬럼 0:  (0.49995, 0.61208, -0.61201)   ‖∙‖ = 0.99998   ← 단위 길이 깨짐
컬럼 1:  (0.00003, 0.70706, 0.70709)    ‖∙‖ = 1.00001
컬럼 2:  (0.86604, -0.35400, 0.35407)   ‖∙‖ = 1.00006

컬럼 0 · 컬럼 1 = 0.00002    ← 직교성 깨짐
컬럼 1 · 컬럼 2 = 0.00005
컬럼 0 · 컬럼 2 = -0.00003
```

Gram–Schmidt 또는 외적 방식으로 이 3 벡터를 가까운 정규직교 상태로 보정 = 정규직교화.

**(B) 단일 회전축 $\mathbf{n}$ 은 별도로 저장되어 있지 않으므로 직접 "깨진다" 라는 개념이 적용되지 않는다.** 행렬 (A) 가 깨지면 거기서 추출한 $\mathbf{n}$ 도 부정확해질 뿐.

> **표현 방식과 (A)/(B) 의 관계**
> - **회전 행렬**: (A) 를 직접 저장. (B) 는 암묵적 추출 대상.
> - **Quaternion**: (B) 를 직접 인코딩 ($\cos(\theta/2), \sin(\theta/2)\mathbf{n}$). 행렬로 변환하면 (A) 도산출.
> - **Euler 각**: 둘 다 저장 안 함 — 단축 회전 레시피 3 개만.

## 짐벌락 (Gimbal Lock)

Euler 각의 본질적 결함. 회전을 세 단축 회전의 곱으로 분해할 때 발생하는 자유도 손실 현상.

### 현상

세 Euler 각 $(\alpha, \beta, \gamma)$ 의 **가운데 각** 이 특정 임계값에 도달하면 세 회전 중 두 회전이 같은 축 둘레 회전이 되어, 세 각으로 만들 수 있는 회전이 사실상 2차원으로 줄어든다.

- Tait-Bryan 컨벤션 (X-Y-Z, Y-X-Z 등 세 축 모두 다름): $\beta = \pm 90°$
- Proper Euler 컨벤션 (X-Y-X, Z-X-Z 등 1번 = 3번): $\beta = 0°$ 또는 $180°$

증상은 "완전히 잠긴다" 가 아니라 — **표현은 가능하지만 유일하지 않고**, 그 자세 근방에서 매끄러운 회전이 깨진다:

- 짐벌락 자세는 두 각의 **합** 으로만 의미를 가진다. 예: $\alpha = 30°, \gamma = 0°$ 와 $\alpha = 0°, \gamma = 30°$ 가 같은 자세.
- 보간 시 가운데 각이 임계값을 지나면 나머지 두 각이 동일 자세를 다른 표현으로 통과해 카메라/객체가 휙 돌아간다.
- 사용자 입력을 두 각 중 어느 쪽으로 매핑해야 할지 결정 불능.

### 원인 — 좌표계 운반 관점

Euler 회전은 행렬 곱셈을 하나씩 적용하는데, **각 회전이 좌표계 자체를 운반** 한다. 결과로 다음 회전의 축이 이전 회전이 옮겨놓은 위치에서 출발하게 된다.

**YXZ intrinsic 컨벤션에서 추적**

초기 로컬 축은 월드 축과 일치: $\mathbf{X} = (1,0,0)$, $\mathbf{Y} = (0,1,0)$, $\mathbf{Z} = (0,0,1)$.

1. **1번 회전 (yaw $\alpha$, 월드 Y 둘레)**
   - 로컬 X 는 XZ 평면 안에서 $\alpha$ 만큼 회전 → $\mathbf{X}' = (\cos\alpha, 0, -\sin\alpha)$
   - 로컬 Y 는 자기 자신 → 그대로
   - 로컬 Z 도 XZ 평면 안에서 회전

2. **2번 회전 (pitch $\beta$, 로컬 X' 둘레)**
   - 로컬 Y, Z 를 X' 둘레 $\beta$ 만큼 회전
   - $\beta = 90°$ 일 때 로컬 Z 가 **월드 Y 방향으로 운반** 됨: $\mathbf{Z}'' = (0, 1, 0)$
   - 즉 **3번 회전축이 1번 회전축(월드 Y)과 일치**

3. **3번 회전 (roll $\gamma$, 로컬 Z'' 둘레)**
   - 로컬 Z'' = 월드 Y → 이 회전은 사실상 **월드 Y 둘레 회전**
   - 1번 회전도 월드 Y 둘레였으므로, $\gamma$ 회전과 $\alpha$ 회전이 **같은 방향만 만들어냄**

→ 세 각의 합성이 결국 2개 독립 방향만 만들 수 있게 됨. 그 두 방향이 만드는 평면에 수직한 방향 한 가지를 잃음.

**일반화: 1번축과 3번축 사이 각도**

월드 Y 와 로컬 Z'' 사이 각도를 계산하면:

$$
\text{angle}(\mathbf{Y}_{\text{world}}, \mathbf{Z}'') = 90° - \beta
$$

| pitch $\beta$ | 1번축 vs 3번축 각 | 상태 |
|--------------|----------------|------|
| 0° | 90° | 완전 직교 — 세 회전이 독립 |
| 45° | 45° | 부분 정렬 — 자유도가 연속적으로 새기 시작 |
| 90° | **0°** | 평행 — 짐벌락 |

→ **연속적으로** 자유도가 약화되다 정확히 90° 에서 완전 정렬. 갑자기 잠기는 게 아니라 매끄럽게 새어나가는 과정.

### 왜 항상 1번축과 3번축의 정렬인가

Euler 분해의 기하 구조가 다음을 강제한다:

| 쌍 | 각도 변화? | 짐벌락 가능? |
|----|----------|-----------|
| 1번축 vs 2번축 | 항상 90° (1번 회전은 자기 축은 안 움직임. 2번축은 1번축에 수직한 평면 안에서만 이동) | ✗ |
| 2번축 vs 3번축 | 항상 90° (2번 회전이 3번축을 자기 평면 안에서만 끌고 다님) | ✗ |
| **1번축 vs 3번축** | 2번 각 $\beta$ 에 따라 $90° - \beta$ 로 변함 | **✓** ($\beta$ 가 임계값일 때) |

→ 짐벌락은 본질적으로 **1번 회전축과 3번 회전축이 같은 직선 위에 놓이는 사건**. 2번축은 기하적으로 항상 두 축에 수직이라 짐벌락에 직접 참여하지 않음.

### 표현 방식별 영향

| 표현 | 짐벌락 |
|------|-------|
| **Euler 각** | 본질적 결함. 어떤 컨벤션을 골라도 임계값에서 발생 (위치만 옮겨감) |
| **회전 행렬** | **저장 자체에는 없음**. 행렬 곱셈 누적은 짐벌락과 무관. 단, 행렬을 Euler 로 **분해해 읽으려고 하면** 추출 과정에 특이점 등장 |
| **Quaternion** | **없음**. axis-angle 을 직접 인코딩하므로 분해 순서 자체가 존재 안 함. 4D 단위 구면 위 보간이라 정렬 특이점도 없음 |

**위상적 시각**

3D 회전 공간 SO(3) 는 어떤 3개 파라미터 좌표계로도 매끄럽게 전부 덮을 수 없다. 지구 표면을 평면 지도로 펼치면 극 근처에서 비례가 깨지듯, Euler 좌표는 가운데 각이 임계값인 자세에서 좌표축이 한 점으로 수렴한다. Quaternion 은 4개 파라미터(잉여 1)로 표현해 이 위상적 제약을 우회한다.

**저장과 짐벌락의 관계 정리**

회전 상태는 매 프레임 다음과 같이 보존되고 갱신된다:

| 저장 방식 | 상태 = | 매 프레임 갱신 | 짐벌락 |
|----------|-------|-------------|-------|
| Euler 각 | $(\alpha, \beta, \gamma)$ 세 숫자 | 입력에 따라 각 갱신 → 매 프레임 $R = R_Y R_X R_Z$ 재생성 | 가운데 각이 임계값일 때 발생 |
| 회전 행렬 | 3×3 = 9개 float | $R_{\text{new}} = R_{\text{delta}} \cdot R_{\text{old}}$ 누적 | 저장에는 없음, Euler 분해 시 등장 |
| Quaternion | 4개 float | $q_{\text{new}} = q_{\text{delta}} \cdot q_{\text{old}}$, 주기적 단위화 | 없음 |

→ "Euler 분해의 세 회전축이 움직인다" 는 표현은 **저장된 데이터** 가 아니라 그 데이터의 의미를 시각화한 것. 실제로 보존·갱신되는 건 위 표의 숫자들.

## 잉여 자유도와 오차 누적

### "직교성을 잃는다" 가 정확히 무슨 의미인가

회전 행렬이 정규직교라는 건 두 조건을 동시에 만족한다는 뜻:

1. **각 컬럼이 단위 길이** — $\|\mathbf{x}'\| = \|\mathbf{y}'\| = \|\mathbf{z}'\| = 1$
2. **컬럼들끼리 서로 직교** — 임의 두 컬럼 내적 = 0

수식 한 줄로: $R^T R = I$.

매 프레임 누적 곱 $R_{\text{new}} = R_{\text{delta}} \cdot R_{\text{old}}$ 가 float 반올림 오차를 누적시키면, 9 개 성분 모두가 미세하게 어긋난다. 결과:

- 컬럼 벡터들의 **단위 길이 깨짐** (‖컬럼‖ ≠ 1)
- 컬럼 벡터들의 **상호 직교 깨짐** (컬럼 간 내적 ≠ 0)
- 정량적으로 $R^T R \neq I$

```
R^T R ≈ ⎡ 1.00024   0.00007  -0.00003 ⎤   ← 대각선이 정확히 1 아님
        ⎢ 0.00007   0.99974   0.00009 ⎥   ← 비대각이 정확히 0 아님
        ⎣-0.00003   0.00009   1.00010 ⎦
```

**기하적 의미**: 행렬이 표현하는 회전된 좌표계의 3 축이 흔들렸다는 뜻. 이 행렬을 객체/카메라에 적용하면:

- **미세 스케일**: 한 컬럼이 1.0001 길이라면 그 방향으로 매 프레임 0.01 % 확대 → 누적 시 객체가 미세하게 부풀거나 줄어듦
- **미세 비뚤림(shear)**: 컬럼들이 정확히 90° 가 아니면 회전 후 격자가 평행사변형처럼 살짝 기울어짐 → 메시가 살짝 찌그러짐
- **본 체인 누적 오차**: 부모 본의 변환을 자식이 누적 곱 → hierarchy 깊을수록 끝 본의 위치/방향이 의도에서 점점 더 벗어남

→ 행렬이 더 이상 **순수 회전** 이 아니라 "회전 + 미세 스케일 + 미세 비뚤림" 의 합성으로 변질된 상태.

점검 코드 예시:

```cpp
float NonOrthogonality(const Matrix3& R)
{
    Matrix3 diff = R.Transpose() * R - Matrix3::Identity();
    return diff.MaxAbsElement();   // 0 에 가까워야 정상
}
```

임계값(예: 1e-4) 초과 시 정규직교화를 호출하면 깨진 3 컬럼을 다시 정규직교 상태로 보정.

### 표현별 잉여 비교

| 표현 | float 개수 | 자유도 | 잉여 | 깨지는 양상 | 복구 |
|------|-----------|--------|------|-----------|------|
| 3×3 직교 행렬 | 9 | 3 | **6** | 컬럼 3 벡터의 단위·직교 동시에 깨짐 | **정규직교화** (Gram–Schmidt 또는 외적, 9 성분 동시 보정) |
| Euler 각 | 3 | 3 | 0 | 깨질 제약 자체가 없음 (대신 짐벌락) | 불필요 |
| Quaternion | 4 | 3 | **1** | 사원수 단위 길이 1 차원만 깨짐 | **단위화 1회** ( $q \leftarrow q/\|q\|$ ) |

**핵심**: 잉여 자유도가 클수록 오차가 새어 들어갈 차원이 많아 복원 작업이 무겁다. 행렬은 6 차원 잉여로 오차가 침투해 한꺼번에 보정해야 하고, Quaternion 은 1 차원 잉여라 길이 하나만 처리하면 끝.

회전 누적이 가장 빈번한 상황 — 카메라/캐릭터/물체의 자세 추적, 본 hierarchy, 물리 시뮬레이션의 angular state — 에서는 Quaternion 이 사실상 표준 선택.

## 정규직교화 알고리즘

직교성이 깨진 세 벡터 $\{v_0, v_1, v_2\}$ 를 가까운 정규직교 기저 $\{w_0, w_1, w_2\}$ 로 보정하는 두 가지 표준 방법.

### Gram–Schmidt

차원에 무관한 일반 알고리즘. 각 입력에서 이전 결과 벡터들에 평행한 성분을 빼내어 직교화 후 정규화한다.

$$
w_0 = \frac{v_0}{\|v_0\|}
$$

$$
w_1 = \frac{v_1 - (v_1 \cdot w_0)\, w_0}{\|v_1 - (v_1 \cdot w_0)\, w_0\|}
$$

$$
w_2 = \frac{v_2 - (v_2 \cdot w_0)\, w_0 - (v_2 \cdot w_1)\, w_1}{\|v_2 - (v_2 \cdot w_0)\, w_0 - (v_2 \cdot w_1)\, w_1\|}
$$

특징:
- **첫 입력 $v_0$ 의 방향이 정확히 보존** 된다. 나머지는 직교화 과정에서 평행 성분이 빠져 방향이 미세하게 움직인다.
- 차원에 무관해 N차원, tangent space (T, B, N) 보정 등 어디든 쓸 수 있다.

### 외적 기반 직교화 (3D 한정)

3D 공간에서만 통하는 단축법. 두 축의 외적이 자동으로 두 축 모두에 직교한다는 성질을 이용.

입력 $\{v_0, v_1, v_2\}$ 에서 $v_0$ 를 기준으로 삼고 두 번째 축을 직접 외적으로 얻는다 (책의 카메라 자세 예시 절차).

$$
w_0 = \frac{v_0}{\|v_0\|}
$$

$$
w_2 = \frac{w_0 \times v_1}{\|w_0 \times v_1\|}
$$

$$
w_1 = w_2 \times w_0
$$

특징:
- 외적 한 번 + 정규화 한 번이라 **연산이 가볍다**.
- 입력 $v_2$ 는 알고리즘에서 **전혀 쓰이지 않는다** — $v_0, v_1$ 두 벡터만으로 직교 기저가 결정된다.

### 두 방식의 결과가 다른 이유

같은 입력에 두 알고리즘을 돌리면 결과가 다르다. 입력:

- $v_0 = (1, 0, 0)$
- $v_1 = (0, 1, 1)$
- $v_2 = (1, 1, 0)$

**Gram–Schmidt 결과**:

- $w_0 = (1, 0, 0)$ — $v_0$ 방향 보존
- $w_1 = (0, 1/\sqrt{2}, 1/\sqrt{2})$ — $v_1$ 을 $w_0$ 에 직교화한 방향
- $w_2 = (0, 1/\sqrt{2}, -1/\sqrt{2})$ — $v_2$ 를 $w_0, w_1$ 에 직교화한 방향

**외적 방식 결과**:

- $w_0 = (1, 0, 0)$ — 동일
- $w_2 = (0, -1/\sqrt{2}, 1/\sqrt{2})$ — $w_0 \times v_1$ 의 방향 ($v_2$ 입력은 무시!)
- $w_1 = (0, 1/\sqrt{2}, 1/\sqrt{2})$ — $w_2 \times w_0$

→ $w_0, w_1$ 은 같지만 $w_2$ 는 **부호가 반대**. Gram–Schmidt의 $w_2$ 는 $v_2$ 를 직교화한 결과라 $v_2$ 방향에 가깝지만, 외적 방식의 $w_2$ 는 $w_0, v_1$ 이 이루는 평면의 수직이라 $v_2$ 와 무관하다.

핵심: **외적 방식은 입력 중 하나의 방향 정보를 버린다**. 기저가 어느 좌표계 손방향(LH/RH)인가에 따라 부호도 달라진다.

## 알고리즘 선택 기준: 보존하고 싶은 축

선택의 기준은 **"보정 과정에서 어느 축의 방향이 흐트러지면 안 되는가"** 다.

- 모든 입력 축이 거의 같은 비중일 때 → 어느 쪽이든 OK, 외적 방식이 빠르다.
- 한 축을 정확히 보존해야 할 때 → **Gram–Schmidt** 를 쓰고 그 축을 **첫 입력으로** 넣는다.
- 두 축의 방향만 의미 있고 셋째 축은 그 두 축으로부터 결정되어도 OK → 외적 방식이 적절.

전형적 패턴:

| 상황 | 보존 대상 | 적합한 방법 |
|------|----------|-----------|
| 카메라 자세, forward 보존 우선 | forward | Gram–Schmidt — forward 를 첫 입력으로 |
| Tangent space (T, B, N) 정리 | N (메시 normal) | Gram–Schmidt — N 첫 입력, $T' = T - (T \cdot N)N$ , $B = N \times T'$ |
| FPS/3인칭 카메라 (world up 정렬) | forward 만 | 외적 방식: $\text{right} = \text{worldUp} \times \text{forward}$ , $\text{cameraUp} = \text{forward} \times \text{right}$ |
| 일반 회전 누적 (가능하면) | — | Quaternion 사용 — 직교화 자체 불필요 |

---

## World up 고정 패턴 vs 자유 회전

매 프레임 자세를 재구성하는 흔한 패턴:

- 입력: forward (사용자 입력으로 변함)
- 참조: worldUp (고정 상수, 보통 $(0, 1, 0)$ )
- 계산:

$$
\text{right} = \text{normalize}(\text{worldUp} \times \text{forward})
$$

$$
\text{cameraUp} = \text{forward} \times \text{right}
$$

이 패턴의 효과:
- 이전 프레임의 right/up은 사용되지 않고 **재생성** 된다 → forward 방향만 누적되고 다른 축은 매번 새로 만들어짐.
- **Roll(기울임) 정보가 매 프레임 소실** 된다. forward 축 둘레의 회전을 누적할 수 없음.
- camera up이 항상 world up 쪽으로 정렬됨 → "하늘이 항상 위" 가 보장됨.

용어 구분:

- **world up**: 세계의 절대 위쪽. 절대 안 변하는 상수.
- **camera up**: 카메라의 로컬 위쪽. forward에 직교하도록 매 프레임 재계산되는 값. forward가 위/아래를 보면 camera up은 world up과 달라진다.

언제 적절한가:

| 적합 | 부적합 |
|------|-------|
| FPS 카메라 | 비행 시뮬레이션 (뱅크/롤 필요) |
| 3인칭 추격 카메라 | 우주 게임, 6DOF |
| AI 시야·look-at 타겟팅 | 캐릭터 머리 본 (head tilt 보존 필요) |
| roll 의도 없는 게임 (멀미 감소) | 일반 물리 시뮬레이션의 각운동 |

자유 회전이 필요한 경우(비행 시뮬, 6DOF)는 **모든 축을 함께 보존** 하거나 **Quaternion** 으로 자세를 추적해야 한다.

## 특이점 (Forward // World up)

World up 고정 패턴에는 본질적 특이점이 있다:

$$
\text{forward} \parallel \text{worldUp} \Rightarrow \text{worldUp} \times \text{forward} = \mathbf{0}
$$

외적 결과가 0벡터이면 정규화가 정의 불능 → right 축을 만들 수 없다.

실제 증상:
- FPS에서 시선을 정확히 정수직 위/아래로 끝까지 올렸을 때 카메라가 뒤집히거나 튐.
- 정수직 근처에서 미세한 입력에도 right 축 방향이 급격히 바뀌어 흔들림 발생.

표준 처리:
- **Pitch 클램프** — 위/아래 회전 각도를 $\pm 89.9°$ 같이 제한 (전형적 FPS 처리).
- **Epsilon 가드** — $\|\text{worldUp} \times \text{forward}\| < \varepsilon$ 일 때 이전 프레임 right를 재사용하거나 보조 참조 축으로 대체.
- 짐벌락이 본질적으로 문제인 경우 — **Quaternion** 으로 전환.

**짐벌락과의 관계**: 이 특이점은 [짐벌락](#짐벌락-gimbal-lock) 과 같은 가족이다 — 둘 다 "회전 표현 방식이 강제하는 자유도 손실" 이라는 공통 본질. 다만 짐벌락은 **Euler 분해의 1번-3번 회전축 정렬** 에서 비롯되는 반면, 이 특이점은 **외적 기반 재구성에서 두 벡터가 평행해지는** 데서 비롯된다. 메커니즘은 다르지만 증상(자유도 1 손실, 보간 끊김, 입력 매핑 모호)은 유사하고, 해결책도 동일하게 Quaternion 으로의 전환이 근본 해법.

## Quaternion이 직교화 필요성을 줄이는 영역과 한계

회전 누적의 일반적 권장은 Quaternion이지만, 모든 정규직교화 수요를 대체하지는 않는다.

### 직교화가 불필요한 영역 (Quaternion으로 충분)

- 카메라·캐릭터·물체 자세 추적 (회전 누적)
- 회전 보간 (slerp)
- 물리 엔진의 각속도·각운동 적분
- 본/스키닝 행렬의 회전 부분

Quaternion으로 저장하면 직교 행렬이 만들어지지 않으므로 "행렬 직교성이 깨질" 일 자체가 없다. 단위화 1회면 끝.

### 그래도 직교화가 필요한 영역

1. **Tangent space (T, B, N) 계산** — 노멀 매핑에서 필수.
   - 메시 데이터의 tangent가 normal과 정확히 직교가 아닐 수 있다 (모델링 단계 부정확성).
   - 셰이더에서 Gram–Schmidt: $T' = \text{normalize}(T - (T \cdot N) N)$ , $B = N \times T'$ .
   - "회전 누적의 오차" 가 아니라 **데이터 자체** 를 정리하는 작업 — Quaternion과 무관.

2. **Normal만 주어진 평면에서 임의 직교 frame 생성** — procedural geometry, BRDF 방향 샘플링 등.

3. **Look-at 카메라 신규 생성** — forward 만 주어졌을 때 right/up을 외적으로 도출. 오차 보정이 아닌 신규 구성.

4. **외부 입력 자세의 직교성 보장** — 측정 데이터, 보간된 행렬, 외부 포맷에서 읽은 자세 등.

### 결론

자세 누적 행렬의 오차 보정만 따지면 현대 엔진에서는 Quaternion이 주류이므로 책의 카메라 직교화 절차를 그대로 쓸 일은 드물다. 다만 **데이터 정리 용도** 로서의 정규직교화 — 특히 tangent space — 는 여전히 필수.

## 정리

### 한 문장으로

회전·자세 표현·짐벌락·정규직교화는 전부 **"3 개 정규직교 벡터(= 회전된 로컬 좌표계 기저)를 어떻게 저장·관리·보정할 것인가"** 의 다른 측면이다.

### 표현 방식별 핵심

| 표현 | 저장 데이터 | 의미 | 깨지는 양상 | 복구 |
|------|-----------|------|-----------|------|
| **Euler 각** | $(\alpha, \beta, \gamma)$ 3 숫자 | 단축 회전 레시피 | 깨질 제약 없음 (대신 짐벌락) | 불필요 |
| **회전 행렬** | 9 float | 회전된 좌표축 3 벡터 (컬럼) | 단위·직교 동시에 깨짐 | 정규직교화 |
| **Quaternion** | 4 float | 단일 회전축 + 반각 | 단위 길이 1 차원만 | 단위화 1회 |

### 짐벌락의 핵심

- Euler 분해는 회전 3 개를 직렬로 곱하면서 **각 회전이 좌표계를 운반** 한다.
- 가운데 회전이 임계값에 도달하면 **1번 회전축과 3번 회전축이 같은 직선이 되어** 두 회전이 같은 축 둘레 회전이 되고, 자유도 1 손실.
- 1번-2번, 2번-3번 쌍은 기하적으로 항상 90° 유지 → 짐벌락에 참여하지 않음. **본질은 1번-3번 정렬.**
- Tait-Bryan(XYZ 등) 은 $\beta = \pm 90°$, proper Euler(XYX 등) 는 $\beta = 0°/180°$.
- 표현이 본질적 결함이라 어떤 Euler 컨벤션을 골라도 위치만 옮겨갈 뿐 사라지지 않음.

### 직교성 손실의 의미

- 행렬의 **컬럼 3 벡터** 가 단위 길이·상호 직교 조건을 잃는 것 — 즉 회전된 좌표계의 3 축이 흔들림.
- 결과: 행렬이 "회전 + 미세 스케일 + 미세 비뚤림" 으로 변질 → 객체/카메라가 시간 누적에 따라 미세하게 부풀거나 찌그러짐, 본 체인 끝이 의도에서 벗어남.
- 정규직교화는 그 3 컬럼을 가까운 정규직교 상태로 보정하는 작업.

### 회전 행렬의 두 종류 축 정보

| 구분 | 정체 | 정규직교화 대상? |
|-----|------|---------------|
| (A) 회전된 좌표축 3 개 (컬럼) | 회전 후 X·Y·Z 가 향하는 단위 벡터 셋 | **YES** (3 벡터 셋의 정규직교 조건) |
| (B) 단일 회전축 $\mathbf{n}$ | 회전 전체를 단일 축-각 회전으로 환원했을 때의 축 (Euler 정리) | NO (한 벡터에는 정규직교 개념 자체가 안 정의됨) |

### 정규직교화 알고리즘 선택

| 상황 | 보존 대상 | 방법 |
|-----|---------|------|
| 카메라 자세, forward 우선 | forward | Gram–Schmidt — forward 첫 입력 |
| Tangent space (T, B, N) | N (mesh normal) | Gram–Schmidt — N 첫 입력 |
| FPS / 3인칭 (world up 정렬) | forward 만 | 외적 방식: $\text{right} = \text{worldUp} \times \text{forward}$ |
| 일반 회전 누적 | — | Quaternion 으로 회피 |

**핵심**: 알고리즘 선택은 **어느 축의 방향을 흐트러뜨리면 안 되는가** 로 결정.

### World up 패턴과 그 특이점

- 패턴: 매 프레임 forward 만 누적 + worldUp 으로 right/up 외적 재생성. FPS·3인칭에 적합.
- 비용: roll 정보 매 프레임 소실.
- 특이점: forward ∥ worldUp 일 때 외적 = 0 → 처리 필요 (pitch 클램프, epsilon 가드, Quaternion 전환).
- 짐벌락과 같은 가족 — "표현이 강제하는 자유도 손실" 의 다른 변종.

### Quaternion 의 영역과 한계

- **불필요**: 카메라·캐릭터·물체 자세 추적, slerp, 물리 angular state, 본 회전 부분.
- **여전히 필요**: tangent space 정리, normal 로부터 frame 생성, look-at 신규 구성, 외부 자세 데이터 보정 — 이건 "회전 누적의 오차" 가 아니라 **데이터 자체** 를 정리하는 작업이라 Quaternion 으로 회피 불가.

### 실전 권장

- 회전 누적이 본질인 자료는 **Quaternion** 으로 저장. 잉여 자유도 1, 단위화 1회로 복원.
- 행렬을 직접 다뤄야 한다면 주기적으로 **재정규직교화**. 알고리즘 선택은 보존 축 기준.
- World up 패턴은 FPS·3인칭에 적합하나 roll 정보 손실과 forward // worldUp 특이점 동반.
- Quaternion 이 만능은 아님 — tangent space 등 데이터 정리 용도의 정규직교화는 여전히 필수.
