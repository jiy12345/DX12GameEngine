# 책/문서 학습 정리 워크플로우

**적용 시점**: 책, 논문, 외부 문서를 읽으며 학습 내용을 정리할 때 (Luna DX11, Real-Time Rendering 등 모든 외부 학습 자료)

---

## 핵심 원칙

### 0. 책 근거 원칙 (최우선)

**노션·Concepts 어디든, 정리에 들어가는 모든 내용은 반드시 그 책(또는 해당 자료)에서의 근거가 있어야 한다.**

- 책에 명시되지 않은 내용을 "당연히 알 거니까", "일반적으로 그러니까" 식으로 추가하지 않는다
- 추측·일반 상식·다른 자료에서 가져온 내용으로 빈 곳을 메우지 않는다
- 책에 없는 내용을 보강하고 싶으면 **출처를 명시한 별도 섹션**으로 분리하거나, 별도 Concepts 문서로 빼서 그 자료의 출처를 명확히 한다
- 정리하면서 "이 부분 책에서 본 적 있던가?" 의심이 들면 그 페이지로 돌아가 확인 후 인용

**Why:** 학습 정리의 신뢰성. 나중에 다시 읽었을 때 "이게 진짜 책 내용인지, 내 해석인지, 다른 데서 본 건지" 헷갈리지 않게 하기 위함. Concepts 문서로 추출할 때도 출처가 명확해야 다른 자료와 교차 검증이 가능하다.

**How to apply:** 매 섹션 정리 시 책의 해당 부분(페이지/절 번호)을 옆에 두고 작성. 노션 정리 끝에 책 페이지/절 표기 권장. 추출 시 책에 직접 나온 표현·정의·공식·코드만 사용.

### 1. 분리 원칙

학습 자료를 정리할 때는 **저작권 리스크 회피 + 학습 효과 + 엔진 코드 연결**을 모두 챙기기 위해 정리 위치를 분리한다.

| 위치 | 공개/비공개 | 용도 | 작성 자유도 |
|------|------------|------|------------|
| **노션** | 비공개 | 챕터별 학습 노트 (책 흐름 그대로) | 인용·예제·필기 자유 |
| **Git 리포 `Docs/Concepts/`** | 공개 | 일반 개념 문서 (책 의존 없이 본인 언어 재구성) | `documentation.md` 규칙 준수 |
| **Git 이슈** | 공개 | 학습 중 떠오른 엔진 구현 아이디어 | `workflow.md`의 연구/학습 이슈 패턴 |

**왜 분리하는가**:
- 공개 Git 리포에 책 문장·예제·그림을 그대로 옮기면 저작권 침해 소지 (paraphrase여도 책 구조 그대로 따라가는 displacive summary는 위험)
- 비공개 노션에서는 자유롭게 정리 → 학습 효과 극대화
- 일반 그래픽스/수학 지식으로 재구성 가능한 부분만 공개 리포에 → 다른 개발자에게도 도움

## 절차 (장 단위 반복)

학습 자료의 **장(Chapter) 단위**로 아래 7단계를 반복한다. 한 장이 너무 길면 절(섹션) 단위로 쪼개도 되지만, 기본 단위는 장이다.

### 1. 본문 추출
- Claude가 책/문서의 한 섹션 분량을 추출해서 사용자에게 보여줌
- PDF는 `pdftotext` 사용 (Windows MinGW에 설치되어 있음)

### 2. 노션 자동 입력 (비공개)
- Claude가 노션 MCP로 해당 섹션 정리본을 비공개 노션 페이지에 작성
- 인용·예제·필기 자유롭게 포함 (비공개이므로 저작권 부담 없음)
- **사용자가 직접 쓰겠다고 하면 즉시 자동 입력 중단**

### 3. 질문 단계
- 사용자가 정리된 내용에 대해 질문 → Claude가 답변
- 이해도 점검과 보강

### 4. 컨셉트 추출 제안
- 섹션 정리가 끝나면 Claude가 **`Docs/Concepts/` 하위에 일반 개념 문서로 추출할 가치가 있는 항목**을 제안
- 추출 기준: 책 의존 없이 일반 그래픽스/수학/엔진 지식으로 재구성 가능한 것
- 책 특유의 예제·연습문제는 제외

### 5. 문서 초안 작성 + 티키타카
- 사용자가 OK한 컨셉트에 대해 `Docs/Concepts/<주제>/<문서>.md` 초안 작성
- `.claude/guides/documentation.md` 규칙 준수 (목차 필수, 근거 기반, 본인 언어)
- 출처는 하단 "참고문헌" 섹션에 Luna 책 + 다른 자료 같이 명시
- 사용자와 주고받으며 다듬음

### 6. PR 생성
- `.claude/guides/workflow.md`에 따라 브랜치 (`docs/이슈번호`) → 커밋 → PR
- 사용자 최종 리뷰

### 7. 머지
- 사용자가 머지

## 부속 규칙

### 구현 아이디어
학습 중 "엔진에 구현해보고 싶다"는 아이디어가 나오면 별도 이슈로 발행.
- ⚠️ **이슈 생성 전 사용자 컨펌 필수**
- `.claude/guides/workflow.md`의 연구/학습 이슈 패턴 (전략 비교 + 체감 실험 자매 쌍) 활용

### 저작권 가드레일
- 공개 Git 리포에는 책 문장·예제·그림을 그대로 옮기지 않는다
- paraphrase도 책 구조를 그대로 따라가는 displacive summary는 피한다
- Concepts 문서 하단에 "참고문헌" 섹션으로 출처 명시 (Luna 외 다른 자료도 같이)
- 책 그림 대신 직접 그린 다이어그램 사용

### 노션 페이지 위치 및 형식

**위치 (고정)**:
- 데이터베이스: **📚 Books I read** (`https://www.notion.so/27963874d8324052b20cb6fd9a908a8e`)
- 데이터 소스 ID: `collection://e19d08a4-51e9-4cde-a530-c0e4b9a3f005`
- 모든 책/외부 자료 정리 페이지는 이 DB 안에 위치

**페이지 찾기 또는 생성 절차**:
1. 학습 시작 시 먼저 이 DB에서 해당 책 페이지가 있는지 검색 (`notion-search`로 책 제목/저자 검색)
2. **있으면**: 기존 페이지에 이어쓰기 (이미 정리된 부분과 안 겹치게 진행 상황 확인)
3. **없으면**: DB 안에 새 페이지 생성 (아래 형식 따름)

**페이지 형식 (필수 준수)**:
- **제목**: `책 한글명(저자명)` 예: `DirectX를 이용한 3D 게임 프로그래밍 입문(프랭크 D. 루나)`
- **아이콘**: 책 주제에 맞는 이모지 (🖼️ 그래픽스, 📕 게임 엔진, 🧵 멀티스레딩 등)
- **태그**(multi_select): 다음 중 해당하는 것 선택
  - `AI`, `그래픽스 프로그래밍`, `프로그래밍 언어`, `멀티 스레딩`, `멀티 플레이`, `게임 프로그래밍`
- **콘텐츠 구조**:
  ```
  <table_of_contents/>          ← 최상단 자동 목차

  # Part1 ...                   ← 책의 큰 단원 (있을 때)
  ## 1. 챕터명                  ← 챕터
  ### 섹션명                    ← 세부 섹션
    - 본인 언어로 정리한 핵심 요약 (글머리 기호, 강조)
    - 코드 블록 (책 코드 인용 시 ```language)
    - 이미지 (수식·도표는 책 캡처 또는 직접 작도)
    - <mention-page url="..."/>  ← 별도 개념 노션 페이지 참조
  ---                           ← 챕터/섹션 사이 구분선
  ```
- **인용/이미지**: 비공개이므로 책 그림·캡처·코드 자유롭게 포함 가능
- **별도 개념 페이지**: 큰 개념(예: "스왑체인", "Phong 조명 모델")은 노션 안에 별도 페이지로 만들고 `<mention-page>`로 참조 (책 페이지 본체가 너무 커지지 않게)
